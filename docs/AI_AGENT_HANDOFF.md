# Передача проекта Elite Task следующему ИИ-агенту

## 1. С чего начать

1. Прочитать корневой `AGENTS.md`.
2. Прочитать `docs/IMPLEMENTATION_PLAN.md` — это утверждённый план и главный чек-лист проекта.
3. Прочитать `README.md` — там находятся актуальные команды локального запуска.
4. Перед изменением бизнес-логики изучить проверки доступа в `apps/api/app/services/access.py`.
5. Не начинать production-деплой без IP сервера, домена, DNS и SSH-доступа от владельца.

## 2. Что уже реализовано

### Сервер FastAPI

- Асинхронный FastAPI и SQLAlchemy 2 с локальной SQLite через `aiosqlite`.
- JWT-авторизация и роли: руководитель, администратор, менеджер.
- Автоматическое создание локальной схемы и демонстрационных данных.
- Проекты: список, просмотр, создание, редактирование, архивирование, участники проекта.
- Задачи: создание, редактирование, статусы, приоритеты, дедлайны, избранное.
- Подзадачи, чек-листы, соисполнители и локальные вложения.
- Раздельные заметки и комментарии, история существенных изменений.
- Обязательная причина при переводе задачи в статус «Ожидание».
- Представления «Мои задачи» и «Мой день».
- Командная аналитика и детализация задач сотрудника для руководителя.
- Уведомления и WebSocket-канал для мгновенных событий.
- Глобальный поиск по задачам, проектам и сотрудникам с фильтрацией по доступу.
- Typed-схемы ответов и централизованные проверки прав.

### Expo React Native

- Экран входа и хранение пользовательской сессии.
- Профессиональная светлая дизайн-система в стиле современных корпоративных таск-менеджеров.
- Нижняя навигация: «Мой день», «Задачи», «Проекты», «Поиск», «Входящие».
- Карточки задач, быстрые фильтры и состояния загрузки/ошибки/пустого списка.
- Полная карточка задачи: статус, редактирование, чек-лист, подзадачи, файлы, заметки, комментарии, история.
- Создание задач и подзадач с выбором проекта, срока, приоритета, исполнителя и соисполнителей.
- Рабочее пространство проекта с участниками, задачами и архивированием.
- Поиск по задачам, проектам и пользователям.
- Панель команды с переходом к показателям и задачам сотрудника.
- WebSocket-подключение к уведомлениям.
- Адаптация и визуальная проверка основных экранов в мобильном viewport 390×844.

## 3. Права доступа, которые нельзя нарушать

- Руководитель видит все проекты и управляет всеми сущностями.
- Администратор управляет доступными проектами и менеджерами, но не назначает задачи руководителю.
- Менеджер видит только доступные проекты и связанные с ним задачи.
- Менеджер полностью редактирует созданную им личную задачу.
- В назначенной руководителем задаче менеджер меняет только выполнение: статус, причину ожидания, чек-лист, заметки и комментарии.
- Любой новый endpoint обязан проверять проектную видимость и роль, а не полагаться только на фильтрацию клиента.

Полная матрица находится в `docs/IMPLEMENTATION_PLAN.md`.

## 5. Как проверить проект

### API

```powershell
cd apps/api
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Swagger доступен по адресу `http://localhost:8000/docs`.

### Мобильное приложение

```powershell
cd apps/mobile
npm install
Copy-Item .env.example .env
npm run typecheck
npm run doctor:lts
npm run export:android:lts
npm run start:lts
```

На этой машине системный Node 24 нестабилен для Metro. Скрипты с суффиксом `:lts` автоматически используют Node 22 и один worker.

## 6. Что осталось сделать

### Этап D — совместная локальная приёмка

1. Владелец проверяет продукт на реальном Android/iOS устройстве.
2. Проверяются все роли и реальные пользовательские сценарии.
3. Отдельно проверяются часовой пояс, дедлайны, просрочки и потеря сети.
4. Фиксируются замечания владельца по интерфейсу и бизнес-правилам.
5. После правок замораживается объём первой production-версии.

### Этап E — сервер и production-деплой

Выполнять после получения параметров сервера:

1. Перевести БД с SQLite на PostgreSQL через `asyncpg`.
2. Добавить Alembic и первую production-миграцию.
3. Подготовить production env без секретов в Git.
4. Добавить контейнеризацию или systemd-сервисы, health checks и рестарт процессов.
5. Настроить reverse proxy, TLS, домен и CORS.
6. Настроить резервное копирование PostgreSQL, журналирование и наблюдаемость.
7. Перенести вложения в S3-совместимое хранилище и добавить антивирусную проверку.
8. Настроить production API URL и собрать Android/iOS приложения.
9. Провести smoke-тесты ролей, WebSocket, загрузки файлов и восстановления после перезапуска.

### После первой production-версии

1. Push-уведомления через Expo Notifications.
2. Повторяющиеся задачи и фоновый планировщик.
3. Зависимости задач и блокировка следующего этапа.
4. Шаблоны проектов, диаграмма Ганта и расширенные отчёты.
5. Аудит безопасности и нагрузочное тестирование.

## 7. Данные, которые нужно запросить перед деплоем

- IP, ОС и характеристики сервера.
- Домен и доступ к DNS.
- SSH-пользователь и способ аутентификации.
- Требования к Android/iOS распространению.
- Политика хранения вложений и резервных копий.
- Нужные интеграции: корпоративная почта, Telegram, CRM или SSO.

## 8. Правила продолжения разработки

- Сохранять обратную совместимость typed API.
- Для каждого нового backend-правила добавлять сфокусированный тест.
- Перед передачей обязательно запускать `pytest`, `npm run typecheck`, `npm run doctor:lts` и Android export.
- Не добавлять секреты, `.env`, локальную БД, `node_modules`, `.venv` и сборочные каталоги в Git.
- Не заменять серверные проверки доступа клиентскими ограничениями.
- Не усложнять локальный MVP production-инфраструктурой до получения сервера.
