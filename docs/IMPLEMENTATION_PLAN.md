# План разработки Elite Task для ИИ агента

## 1. Цель первой версии

Собрать локально работающий мобильный MVP корпоративного таск-менеджера. Сотрудник видит все назначенные ему задачи из доступных проектов, а руководитель контролирует сроки, прогресс и загрузку команды.

Первая версия должна быстро реагировать на действия пользователя, не дублировать задачи между проектом и личным списком и сохранять строгие права доступа.

## 2. Принятые технические решения

| Область | Решение | Причина |
| --- | --- | --- |
| Мобильный клиент | Expo React Native и TypeScript | Быстрый локальный запуск на Android, iOS и web |
| Сервер | FastAPI и async SQLAlchemy | Низкая задержка, строгие схемы, удобный OpenAPI |
| Локальная БД | SQLite через `aiosqlite` | Запуск без Docker и внешних сервисов |
| Продакшен БД | PostgreSQL через `asyncpg` | Масштабирование и надёжные конкурентные записи |
| Авторизация | JWT access token | Удобно для мобильного клиента |
| Реальное время | WebSocket плюс обычный REST | Мгновенные уведомления без усложнения основных операций |
| Файлы | Локальное хранилище в MVP, S3-совместимое после сервера | Простой старт и понятный путь миграции |

## 3. Границы MVP

### Обязательно

1. Авторизация и роли: руководитель, администратор, менеджер.
2. Проекты, участники и архивирование.
3. Задачи и подзадачи с постановщиком, ответственным и соисполнителями.
4. Статусы: новая, в работе, ожидание, на проверке, выполнена, отменена.
5. Обязательная причина при переводе задачи в ожидание.
6. Дедлайн, приоритет, избранное, чек-лист.
7. Раздельные заметки и комментарии.
8. История существенных изменений.
9. «Мои задачи» без копирования записей, с фильтрами «Все», «Сегодня», «Неделя», «Просроченные», «Завершённые».
10. «Мой день» с краткими счётчиками и приоритетными задачами.
11. Панель команды для руководителя.
12. Базовые уведомления и WebSocket-события.
13. Глобальный поиск по задачам, проектам и сотрудникам с учётом прав доступа.
14. Подзадачи, загрузка файлов и управление участниками проекта.

### Текущий статус локального MVP

- Этапы A–C реализованы.
- Основные сценарии руководителя, администратора и менеджера проверены на локальных демо-данных.
- Интерфейс адаптирован для мобильного экрана и визуально проверен в основных сценариях.
- Backend-тесты, TypeScript-проверка, Expo Doctor и Android export входят в финальную локальную проверку.
- Этапы D–E завершаются после пользовательской приёмки и получения параметров сервера.

### После локальной проверки

1. Push-уведомления через Expo Notifications.
2. Повторяющиеся задачи и фоновый планировщик.
3. Зависимости задач с блокировкой следующего этапа.
4. Шаблоны проектов, диаграмма Ганта и расширенные отчёты.
5. S3-совместимое файловое хранилище и антивирусная проверка.
6. Резервное копирование, аудит безопасности и наблюдаемость.

## 4. Этапы работы агента

### Этап A. Основа репозитория

- Создать монорепозиторий `apps/api` и `apps/mobile`.
- Добавить `.env.example`, инструкции запуска и демо-данные.
- Зафиксировать модели ролей, статусов и приоритетов.

Критерий готовности: новый разработчик запускает API и клиент по README.

### Этап B. Сервер MVP

- Реализовать async подключение к БД и автоматическое создание локальной схемы.
- Реализовать JWT-вход и получение текущего пользователя.
- Добавить endpoints проектов, задач, чек-листа, заметок, комментариев, уведомлений и команды.
- Централизовать проверки доступа.
- Добавить WebSocket для уведомлений.
- Добавить тесты ключевых правил.

Критерий готовности: `pytest` проходит, Swagger позволяет выполнить основной сценарий от входа до завершения задачи.

### Этап C. Мобильный MVP

- Экран входа.
- Нижняя навигация: «Мой день», «Проекты», «Мои задачи», «Команда» или «Уведомления» по роли.
- Список задач с быстрыми фильтрами и обновлением свайпом.
- Карточка задачи с изменением статуса и отображением чек-листа, заметок, комментариев и истории.
- Обработка состояний загрузки, пустых списков и ошибок сети.

Критерий готовности: основной сценарий работает на Expo Go или эмуляторе с локальным API.

### Этап D. Совместная локальная приёмка

- Проверить роли на разных демо-аккаунтах.
- Проверить часовой пояс, дедлайны и просрочки.
- Проверить потерю сети и повтор запросов.
- Собрать обратную связь по экранам и бизнес-правилам.
- Зафиксировать список изменений перед деплоем.

### Этап E. Подготовка к серверу и деплой

Выполнять только после получения параметров сервера.

- Переключить БД на PostgreSQL и добавить Alembic-миграции.
- Настроить reverse proxy, TLS, домен и секреты.
- Добавить контейнеры, health checks, резервное копирование и журналирование.
- Перенести файлы в S3-совместимое хранилище.
- Собрать Android/iOS build и настроить production API URL.

## 5. Права доступа

| Действие | Руководитель | Администратор | Менеджер |
| --- | --- | --- | --- |
| Видеть доступный проект | Да | Да | Да |
| Управлять участниками | Да | Да | Нет |
| Назначать задачу руководителю | Да | Нет | Нет |
| Назначать задачу менеджеру | Да | Да | Только себе |
| Полностью редактировать чужую задачу | Да | Если создал или управляет проектом | Нет |
| Обновлять выполнение назначенной задачи | Да | Да | Да |
| Смотреть командную аналитику | Да | Да | Нет |

Менеджер может полностью редактировать созданную им личную задачу. В задаче, назначенной руководителем, менеджер меняет только выполнение: статус, причину ожидания, чек-лист, заметки и комментарии.

## 6. Контроль качества

- API: тесты авторизации, фильтров, обязательной причины ожидания и прав менеджера.
- Клиент: строгая TypeScript-проверка и отсутствие неявных `any`.
- Производительность: списковые endpoints используют ограничение выборки и индексы по ответственному, статусу и сроку.
- Безопасность: пароль хранится как PBKDF2-хеш, JWT имеет срок действия, CORS задаётся через окружение.
- Приёмка: сценарии руководителя и менеджера проверяются отдельно.

## 7. Данные, нужные перед деплоем

1. IP и операционная система сервера.
2. Домен и доступ к DNS.
3. SSH-пользователь и способ выдачи доступа.
4. Требуемые Android/iOS каналы распространения.
5. Политика хранения файлов и резервных копий.
6. Нужна ли интеграция с корпоративной почтой, Telegram или CRM.
